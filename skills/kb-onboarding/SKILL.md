# KB Onboarding — 让 agent 会问，而不是让用户会问

> **用户说「不知道问啥」时，问题不在用户身上。**
> 让人「写下你觉得重要的东西」从来没用过——**必须有一个外部提问者来挖**。

## 0. 为什么需要这个

「不知道问啥」是三件事叠在一起，只解一件是解不开的：

| 症结 | 解法 |
|---|---|
| 不知道库里有什么 → 没地图，无从问起 | **冷启动地图**：agent 先读库，给出基于用户真实痕迹的选项 |
| 不知道什么值得记 → 不知道什么算「知识」 | **采访者纪律**：问的是「已经在用户脑子里、但从没写下来」的东西 |
| 没看到记了有啥用 → 第三次就弃用 | **回看闭环**：每次收尾必须说「记了什么 + 我下次会记得什么」 |

前两个来自两个现成范式的合体：

- **`grill-me`**（Matt Pocock）——*动手前*把需求问清楚，向前；纪律可整套照抄
- **`knowledge-grill`**（ymendel）——*把已有但未记录*的隐性知识抽出来，向后

本技能是后者的通用版：**采访一个「知道自己很多事、但不知道什么值得写」的人**。

## 1. 铁律（照抄 grill-me，违反即失败）

1. **一次只问一问。** 一炮打 10 个问题是本技能的头号失败模式。用户会懵、会敷衍、会走。
2. **每问必带推荐答案。** 原话是 *"Defaulting to 'what do you think?' is lazy."*
   给用户猜一个最可能的，对方只需说「对 / 不对，其实是 XX」。**能让人只需一个字就能纠正你**。
3. **先读库，再开口。** `grep`/读文件能查到的，绝不问。省下的一问是白赚的。
4. **问依赖顺序。** 一题的答案会改变下一题 → 必须先问前面那题。别并行问两条相关的。
5. **不要替用户回答。** 失败模式：agent 自问自答、一口气抛完所有问题、没有推荐答案——那就是它在即兴采访，不是在跑这个技能。
6. **不追问不重要的。** 每次深挖 2–3 层就够，别把人逼成审讯。

## 2. 三阶段流程

### 阶段 0 — 冷启动（用户说「不知道问啥」时）

**先跑地图扫描**（不要靠印象猜用户有什么）：

```bash
python3 skills/kb-onboarding/scripts/kb_map.py --vault <库根目录>
```

**库根目录怎么定**（顺序照做，别跳）：① 用户明确给了路径就用它；② 当前工作目录下若存在 `_raw/` 或 `_wiki/`，那就是库根；③ 都不满足就问一句「你的库在哪个文件夹？」——**绝不要拿别的库凑数**（实测踩过：会话默认库与用户想聊的库不是同一个，scan 出来几百条无关内容）。

脚本产出三类线索，**优先级从高到低**：

1. **未闭环线索**（最高价值）：上周/上月说过但没有下文的事 → 问「后来呢？」
2. **已有内容的延伸**：库里某主题有料 → 问下一个具体问题
3. **空白区**：某层/某类模板还是空的 → 但**不要说「你这里空着」**，要说人话

然后给出 **3 个选项**，每个都必须满足：

- ✅ **一句话就能答完**（降低门槛，别给人出作文题）
- ✅ **具体到用户自己的痕迹**（「你上周说想重新开始跑步，后来跑了吗？」）
- ❌ 不是通用人生问卷（「你的人生目标是什么？」是废题）

**冷启动开场白范式**：

> 我翻了下你的库：工作类内容不少，**有几个板块还空着**。今天聊哪个？
> ① 上周你说想重新开始跑步，后来跑了吗？（一句话就行）
> ② 最近有没有想记又懒得记的小事？我帮你顺手记一笔
> ③ 就说说今天最烦的一件事

### 阶段 1 — 深挖（一次一问 + 推荐答案）

每一轮只做一件事：

```
Q1/3：他是想找你确认哪件事？
推荐答案（我猜）：是上次那个数据口径的事，还是排期的问题？——你改一下就行。
```

要点：

- **口语化，不用术语。** 别问「你的认知飞轮」，问「你当时怎么想的」。
- **明确允许跳过。** 「这个跳过也行」——让人有退路，用户才敢继续。
- **挖的方向**是「用户脑子里已经知道、但从没写下来」的：**决策背后的理由、踩过的坑、别人不知道的约束、当时的真实感受**。
  *知识库里最容易丢的就是「为什么这么做」，因为持有者自己都注意不到它缺失了。*

### 阶段 2 — 落盘 + 回看（决定用户会不会来第二次）

**落盘：agent 静默决定落点，绝不让用户学四层结构。**

| 内容 | 落点 |
|---|---|
| 原话、聊天记录、日记 | `_raw/`（一字不改） |
| 提炼出的概念/方法论 | `_wiki/concepts/` |
| 关于某个人的事实 | `_wiki/people/` |
| 新想法 | `_wiki/ideas/`（status: seed） |
| 做出的决定 | `_wiki/decisions/` |
| 工作中产生的中间产物 | `_workspace/` |

并按库的双维护规则更新 `_wiki/index.md` 与 `_wiki/log.md`。

**回看（必做，缺一不可）**：

> 今天存了 2 条：`_raw/journal/2026-09-20`（原话）+ `_wiki/concepts/某方法`。
> **我下次会记得：这类话题你更想先自己理清再记**——下次聊到，我会先问一句。

「我下次会记得 X」是让人回访的**唯一理由**。没有这一句，再好的提问也会在第三次被弃用。

## 3. 被动采集（稳态，比正式访谈更重要）

访谈是**上坡的引桥**，日常聊天才是正桥。在普通对话里顺手问一句：

> 这段挺值得存的，要记一下吗？（记 / 不用 / 我改两句再记）

**不要每句都问**——一天最多 2–3 次，否则变骚扰。

## 4. 失败模式速查

| 症状 | 原因 | 修法 |
|---|---|---|
| 一次抛 10 个问题 | 没跑这个技能，在即兴采访 | 立刻收回，改一次一问 |
| 全是「你觉得呢？」 | 偷懒，没给推荐答案 | 每问必带「我猜是 XX」 |
| 问的都是通用问卷 | 没读库就开口 | 先跑 `kb_map.py` |
| 它自己把答案写完了 | 替用户回答 | 删掉，重新问 |
| 用户聊完没下文 | 缺回看闭环 | 补「记了什么 + 下次会记得什么」 |
| 用户不知道聊什么 | 选项是开放题 | 换成 3 个一句话能答的具体选项 |

## 5. 何时结束

- 用户明确说「今天到这」/「累了」→ 立刻收，跑阶段 2 回看
- 一轮访谈 **6–10 个问题**是舒适上限，别贪
- 结束时给用户一个**下次的钩子**：「下次我们接着聊 XX」——降低第二次启动成本
